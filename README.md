# 私享衣橱 · BOUDOIR

一个把「衣柜管理」和「角色扮演聊天」缝在一起的单文件 PWA。

拍照入柜，AI 自动识图打标签；然后挑一位你自己写的角色，让他翻你的衣柜、结合当天天气帮你搭一套、再毒舌点评两句。

- **整个 App 就是一个 `index.html`**，没有后端、没有构建、没有依赖。
- **数据全部存在你自己的手机/浏览器里**，不上传任何服务器。
- **AI 用你自己配的接口**（任何 OpenAI 兼容的中转站都行），Key 只存在本机。

## 快速开始

1. 把 `index.html` 放到任意一个 **https 或 localhost** 的地方打开（见 [部署与安装](#部署与安装)）。
2. 进 **设置 → 接口 → AI 接口配置**，填三样：
   - **Base URL**：填到 `/v1` 为止，例如 `https://api.openai.com/v1`
   - **API Key**
   - **模型**：想用识图就填一个带视觉能力的（`gpt-4o`、`gemini-2.x`、`claude-3.5+`、`Qwen-VL` 等）
3. 点「**测试连接**」，看到 ✅ 就通了。
4. 回衣橱，点右下角 **＋** 传几张衣服照片，点「✨ 一键识图并全部入柜」。
5. 进 **设置 → 角色 → ＋ 新建一位**，写好名字和人设。
6. 去 **试衣间**，选他，点「让他从衣柜里帮我挑一套」。

> 没配接口也能用：衣橱、手动打标签、搭配册、导入导出都不需要 AI。只是识图和聊天用不了。

## 功能一览

### 👗 衣橱

- 多选 / 拖拽 / `Ctrl+V` 粘贴上传，**一次最多 50 张**
- 自动等比压缩：缩略图 300px + 高清图 1080px，体积砍掉约 95%，不拉伸
- **AI 识图自动填标签**：认出品类、起名字、打标签、写备注、生成英文生图提示词
  - 单张：填进当前表单，你可以改完再存
  - 批量：每张单独识别、单独入柜（不是共用一套标签）
  - 中途某张失败不影响其它张，失败的照样无标签入柜，回头手动补
- **标签按维度归档**：颜色 / 材质 / 版型·细节 / 风格·场合 / 季节 / 厚薄程度 / 角色绑定，可自建维度
- 分类管理（默认：上装、下装、连衣裙、内衣·睡裙、鞋履、配饰·饰品、特殊道具、未分类）
- 按名字、标签搜索
- 长按进多选：全选 / 批量打标签 / 改分类 / 去搭配 / 删除
- **回收站**：删掉的衣服先进回收站，可还原

### 🪞 试衣间

两种玩法：

**① 我自己搭配** — 自己选好几件，直接存进搭配册，或者请角色点评。

**② 让角色帮我搭** — 分四步：

| 步骤 | 说明 |
|---|---|
| 挑一位角色 | 他会用自己的人设和口吻 |
| 从哪里挑 | **整个衣柜随他挑**（不用你先选）／ 只在我选的几件里挑 |
| 搭配方式 | **只看文本**（读名字标签备注，快且省）／ **真的看图**（更准但更慢更费） |
| 你的要求 | 可以不填。填了优先照你的要求，不填就按他自己的审美 |

- 「整个衣柜 + 识图」时：先按标签粗筛出 N 件候选（N = 识图张数），再逐张看图精选。看过的图在本次打开期间会记住，重试不用重新看。
- 结果给出：**这一套**怎么穿 + **点评**（拆成聊天气泡）+ 英文提示词 + 用到的衣服缩略图
- 可以**画返图**（需要接口支持 `/images/generations`）、**存进搭配册**、**发到私聊**

### 💬 聊天

- 多角色，每位角色独立的人设、开场白、头像、气泡颜色
- **世界书**：按关键词触发的设定条目，也可以设成常驻
- **长期记忆**：可手动总结，也可以每 N 轮自动总结
- **像真人发消息一样分条发**：一个意思一个气泡，可以连发几条
  - 流式接口：他写完一行就冒出一个气泡
  - 非流式接口：整段拿回来后，一条条停顿着冒出来
- 两个发送键：**猫爪** = 只发出去先不让他回（可以连发几句攒着）；**十字星** = 让他把你攒的这几句一起看完再回
- 长按消息可以单独删
- 聊天外观：背景图、背景压暗、字号、字体、双方气泡文字颜色

### 📒 搭配册

- 衣橱统计（在柜 / 回收站 / 已存搭配数，按分类和标签维度汇总）
- 存下来的每套搭配可以改名、删除

## 设置项说明

设置分两层：

- **通用设置**（所有角色共用）：接口、回复方式、识图、天气与时间、角色陪伴、角色管理、数据
- **角色私人设置**（每位角色一份）：我是谁、记忆、衣橱联动、聊天风格、聊天外观

### 接口

| 项 | 说明 |
|---|---|
| 预设 | 配好一套可以存下来，以后一键切换 |
| Base URL / Key / 模型 | 填到 `/v1` 为止；Key 只存本机 |
| 拉取模型列表 | 拉到以后点模型框右边的 ⌄ 就能挑 |
| 测试连接 | 发一条极短的请求验证 |

### 回复方式

- **自动**（推荐）：先试流式，接口不支持就自动转非流式，并记住结论
- **强制流式** / **强制非流式**：有些中转站流式会断，选非流式最稳

### 识图

- 可以单独指定一个**带视觉能力的模型**（留空 = 跟聊天用同一个）
- 清晰度：节省 512px / 标准 720px / 高细节 1024px

### 天气与时间

- 日期、星期、几点、季节**始终**会告诉角色，不依赖网络
- 打开「角色可以读取天气」后，再加上当地天气、气温、体感、全天温差、降水概率、湿度、风速、紫外线
- 定位二选一：
  - **用手机定位**（需要 https 页面 + 允许位置权限）
  - 关掉定位，**手填城市**（建议填英文，如 `Shanghai` / `Tokyo`）。开着定位但定位失败时也会用它兜底
- 点「测试获取」能看到拿到的具体数据和当地时间
- 天气缓存 30 分钟，过期后在下次调用 AI 前自动刷新；拿不到就用旧的，不会卡住聊天
- 他会在合适的时候自然地带进话里（天冷让你加衣、下雨提醒带伞），不会像播报天气

> 天气数据来自 [Open-Meteo](https://open-meteo.com/)（免费、无需 Key），反查城市名用 BigDataCloud。这是本 App 唯二会联网的第三方地址（另一个是你自己配的 AI 接口）。

### 聊天风格（角色私人）

| 项 | 说明 |
|---|---|
| **允许他写动作、神态和心理描写** | 勾上可以穿插 `*抬眼看你*`；不勾则强制只输出说出口的话，万一他还是写了，星号和括号里的描写会被自动删掉（括号里带数字的会保留，比如「（体感 10°C）」） |
| **他一次最少/最多说几句** | 各 1~10 句，一句 = 一个气泡。在这个范围内由他自己决定发几条。气泡**按他分的句来拆，不按字数硬切**；超上限才合并，不够下限才在句号处补切 |
| 回复温度 | 0.7 稳 / 0.95 推荐 / 1.1 放得开 |

### 衣橱联动（角色私人）

他能看到多少衣服：**全部**（能说出具体衣服名）／ 只给统计概况（省 token）／ 不给。

### 记忆（角色私人）

记得最近多少轮（20/40/80），以及每多少轮自动总结一次（可关）。

## 角色陪伴（小头像）

在**衣橱**和**试衣间**页面，左下角会有一个角色小头像，他会在旁边冒台词气泡。

**台词不额外花钱** —— 全部跟着本来就要发的那次接口一起生成：

| 场景 | 他什么时候说话 |
|---|---|
| 识图入柜 | 识图返回的数据里多带一句，每认出一张说一句 |
| 帮你挑衣服 | 开场、挑的过程中、挑完收尾各一句；识图模式下每看一件说一句 |
| 请他点评 | 第一反应 + 收尾 |
| 手动入柜 / 存搭配 / 随机抽 | 这些不调接口，用本地预设的短句 |

**操作：**

- **按住拖动** —— 可以拖到屏幕任意位置，松手自动记住。拖到右半边时气泡会自动改成朝左展开。位置按比例存，转屏或换设备都不会跑到画面外。
- **单击** —— 正在说话就收起气泡；没说话就重看他上一句。
- **双击** —— 把他收起来（等同于关掉陪伴）。会弹一个「让他回来」的按钮，也可以去设置里重新打开。

**「正在看」卡片**：识图时头像上方会显示他当前正在看的那件衣服的缩略图、名字和进度（如「正在看 4/10」），所以一次看好几件也知道他这句说的是哪件。

> 上传识图时抽屉会盖住悬浮气泡，所以那种情况下台词会同步显示在抽屉里，带照片缩略图。

## 数据存在哪 / 怎么备份

### 存储

三级降级，哪个能用用哪个：**IndexedDB**（主，库名 `boudoir_closet`）→ **localStorage** → **内存**（兜底，关掉就没了）。

### 键位

| 键 | 内容 |
|---|---|
| `cfg` | 分类、标签池、试衣间选项 |
| `it:<id>` | 衣物元数据 + 缩略图 |
| `im:<id>` | 衣物高清图 |
| `lk:<id>` | 搭配册记录 |
| `roles` | 角色表（**含每位角色的私人设置**：我是谁、外观、聊天偏好） |
| `msg:<roleId>` | 聊天记录 |
| `mem:<roleId>` | 长期记忆 |
| `wb:<roleId>` | 世界书 |
| `ai:cfg` / `ai:presets` / `ai:models` | 接口配置 / 存的预设 / 拉取到的模型列表 |
| `wx:cfg` / `weather` | 天气设置 / 天气缓存 |
| `buddy:cfg` | 角色陪伴的开关、固定角色、小头像位置 |

> `me` 是早期版本的用户人设键，现在只会被读取一次做迁移，之后数据都在 `roles` 里。

### 备份：导出

「**导出全部数据（整机备份）**」是真正的全量备份，设置里和衣橱「更多」里是同一个功能，文件名形如 `boudoir_backup_20261019.json`，内容包括：

- 分类、标签池、**所有衣物（含高清图）**、搭配册
- **所有角色**，连各自的私人设置（我是谁 / 聊天外观 / 聊天风格）
- **每位角色的聊天记录、长期记忆、世界书**
- 接口配置、存的接口预设、天气与时间设置、角色陪伴设置（含小头像位置）

导出前会弹一个面板问 **API Key 要不要一起带**，两个选项都写明了后果：

| 选项 | 说明 |
|---|---|
| **带上 Key** | 换手机后不用重新填接口。但这个文件就等于你的钥匙，别发给别人、别传网盘 |
| **不带 Key** | 更安全。导入后自己再填一次 Key 就行，Base URL 和模型名还是会帮你带过去 |

还有「**先不导出**」可以直接退出，不会生成文件。没配 Key 的话不会问这一步。

### 备份：导入

导入完整备份时会弹面板让你选：

| 方式 | 做什么 | 什么时候用 |
|---|---|---|
| **完全恢复** | 先清掉这台设备上现有的全部数据，再按备份还原，完成后自动重载页面 | 换手机、重装 |
| **只做补充** | 衣服追加进现有衣柜；**只补上本机没有的角色**（连它们的聊天一起）；你现在的角色、聊天和设置一律不动 | 合并两个衣柜、从别人那儿拿几个角色 |

细节：

- 选「完全恢复」后还有一次确认，那一步可以**改选「只做补充」**，也可以直接退出。任何一步退出都不会动到数据。
- 面板上会先告诉你这份备份里有多少件衣服、多少位角色、多少条对话，带没带 Key。
- 如果备份里**没带 Key**，恢复时会**保留这台设备原来填的 Key**，不会把你弄成连不上接口。
- 「只做补充」时，角色 id 已存在就整个跳过（不会覆盖你现有的聊天），完成后会告诉你跳过了几位。
- 「只做补充」时，衣物 id 冲突会**自动分配新 id**，所以**同一个文件导入两次会得到两份衣服**。搭配册同理。
- 老版本只含衣橱的备份（`my_closet.json`，version 3）照样能导入，会直接走「只做补充」，不会问恢复方式。

### 危险操作

设置最底下有「清空聊天记录」和「删除所有数据」，删了找不回来。**动手前先导出一份。**

## 部署与安装

### 必须用 http(s)

直接双击打开（`file://`）大部分功能能用，但有三个限制：

| 限制 | 原因 |
|---|---|
| ❌ 装不到桌面、没有离线缓存 | Service Worker 只在 http(s) 下注册 |
| ❌ 定位用不了 | 浏览器不允许非安全上下文定位（**关掉定位、手填城市即可**） |
| ⚠️ AI 接口可能连不上 | 跨域（CORS）被拦。中转站允许跨域就没问题 |

### 本地起一个

```bash
# 进到 index.html 所在目录，任选一个
python -m http.server 8080
npx serve .
php -S localhost:8080
```

然后浏览器开 `http://localhost:8080`。

### 放到线上

丢进任何静态托管（GitHub Pages、Cloudflare Pages、Vercel、自己的 Nginx）都行，只要是 https。
因为只有一个 html 文件，直接上传就完事。

### 装到手机桌面

设置 → 数据 → 「装到手机桌面」会给出对应浏览器的步骤。
装好后以独立 App 形式运行（全屏、有自己的图标、适配刘海屏和小白条）。
manifest 和图标是运行时用 JS 注入的，不需要额外文件。

## 已知限制

- **衣柜很大时**：喂给 AI 的清单超过约 3.6 万字会截断，回复里会说明有多少件没列出来。
- **识图很费额度**：「整个衣柜 + 识图」每次还要多一次粗筛请求，再加 N 次看图。嫌贵就用「只看文本」，把标签打细一样准。
- **返图需要接口支持生图**，很多中转站只有对话没有 `/images/generations`。
- **搭配册里存的旧点评**显示方式没变，不会拆成气泡。
- **旧聊天记录**里以前那种一大段的回复，没有换行就还是一个气泡。新回复本来就是一条一个气泡。
- **高清图很占空间**。IndexedDB 一般够用，但如果降级到了 localStorage（约 5MB），存不了几件。
- 这是给手机竖屏设计的，电脑上打开能用，但布局是窄屏的样子。

## 改代码的话

- 整个 App 就一个 `index.html`，结构：`<style>` → `<body>` 各页面 DOM → 一个大 `<script>`。
- 脚本里按编号分段（基础工具 / 接口 / 数据层 / 渲染 / 页面与事件 / 设置 / 聊天…），搜中文注释最快。
- 几个容易踩的地方，代码里都写了注释，改之前先读一眼：
  - `#app` 和 `.stage` 必须保持 `overflow:clip`。换回 `hidden` 会让外壳变成可滚容器，键盘弹出时会把收起的抽屉顶上来且关不掉。
  - 要把输入框挪进可见区，用 `nudgeIntoView()`，**不要用 `el.scrollIntoView()`**，原因同上。
  - 气泡拆分统一走 `splitBubbles()`，不允许描写时统一走 `stripActs()`。
  - `Buddy.AV` 的值要和 CSS 里 `.buddy-av` 的宽度保持一致。
- 改完建议至少验证：语法、元素 id 没重复、没引用不存在的元素。

## 隐私

- 所有数据只存在你自己的设备上，没有任何服务器收集。
- API Key 只存在本机，只在调用你自己填的接口时发出去。
- 联网只有三个去向：你自己配的 AI 接口、Open-Meteo（天气，仅在开启时）、BigDataCloud（把坐标反查成城市名，仅在用定位时）。
- 衣服照片只有在你主动用识图功能时，才会发给你自己配的那个 AI 接口。
