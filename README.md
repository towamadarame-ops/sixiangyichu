# 私享衣橱 · BOUDOIR

一个跑在手机上的**私人衣橱 App**。你把自己的衣服拍照存进去，它帮你管理、搭配，还能让你自己创建的角色翻你的衣柜给你出主意、陪你聊天。

**所有照片、聊天记录、API Key 只存在你自己的设备上，不上传任何服务器。**

## 它能干嘛

**衣橱管理**
- 一次最多传 50 张衣服照片，自动压缩、自动保持比例
- AI 看图自动打标签（品类、颜色、材质、版型、风格）
- 自定义分类和标签维度，想加什么加什么
- 打字即搜，搜名字、品牌、标签、备注

**搭配**
- 自己挑衣服，或让 AI 从整个衣柜里帮你挑
- 角色会点评这套搭配，可以只看文字，也可以让他真的看图
- 生成"你穿这套"的效果图
- 存进搭配册，随时回看

**角色与聊天**
- 自己创建任意多个角色，各有名字、头像、人设、开场白、气泡颜色
- 完整的角色扮演聊天，长期记忆 + 世界书
- **角色能看到你整个衣柜**，聊穿搭时会具体说出衣服的名字
- 搭配好的套装可以直接发进聊天让他点评

## 怎么用起来

### 第一步：部署

这是一个**单文件应用**——整个 App 就是一个 `index.html`，没有任何依赖，不需要构建。

**方式一：直接打开（试用）**

双击 `index.html` 就能用。所有功能都正常，唯一的限制是**没法装到手机桌面**（浏览器要求必须是网址）。

**方式二：传到静态托管（推荐）**

随便找一家免费的静态托管传上去就行：

| 平台 | 怎么做 |
|---|---|
| **GitHub Pages** | 新建仓库 → 上传 `index.html` → Settings → Pages → Source 选 `main` 分支 → 等一两分钟 |
| **Cloudflare Pages** | 登录 → Create a project → Direct Upload → 把文件夹拖进去 |
| **Vercel / Netlify** | 把文件夹拖到首页的上传区，秒部署 |

传好以后你会拿到一个网址，用手机浏览器打开它。

> 注意：文件名必须是 `index.html`，这样访问网址根目录就能直接打开。

### 第二步：配 AI 接口

打开 App 后会自动跳到设置页（因为还没配接口）。你需要填三样东西：

| 填什么 | 说明 | 例子 |
|---|---|---|
| **Base URL** | 到 `/v1` 为止，**不要**带 `/chat/completions` | `https://api.openai.com/v1` |
| **API Key** | 你的密钥 | `sk-xxxxxxxx` |
| **模型** | 想用识图就得选支持看图的模型 | `gpt-4o` |

填完点「**测试连接**」，看到 `✅ 通了` 就成了。

**关于模型**：识图（自动打标签、让他看衣服照片）需要模型支持视觉能力。这些都可以：

- `gpt-4o` / `gpt-4o-mini`
- `gemini-2.0-flash` / `gemini-2.5-flash` 等 Gemini 系列
- `claude-3-5-sonnet` 等 Claude 系列
- `Qwen/Qwen2.5-VL-72B-Instruct` 等通义千问 VL 系列

如果你想**聊天用便宜的、识图用贵的**，可以在「设置 → 识图」里单独指定识图模型。

**预设**：配好一套之后可以点「存为预设」存下来（连 Key 一起存）。以后在下拉里一键切换，不用重新填。

### 第三步：装到手机桌面

在「设置 → 数据 → 装到手机桌面」里点一下，会弹出**针对你当前设备的分步图文说明**。

**iPhone / iPad 需要特别注意**（Apple 的限制，不是 bug）：

1. 必须用 **Safari** 打开（Chrome、微信里都装不了）
2. 点屏幕**底部中间**的分享按钮（方框里一个向上箭头）
3. 在弹出菜单里**往下滑**，找到「**添加到主屏幕**」
4. 右上角点「添加」

装好之后从桌面图标打开是全屏的，没有地址栏，跟原生 App 一样。数据还是同一份。

**安卓**：浏览器右上角「⋮」→「安装应用」或「添加到主屏幕」。

**如果菜单里找不到安装选项**，多半是因为：
- 网址不是 `https://` 开头
- 用的是微信/QQ 内置浏览器（点右上角「···」→「在浏览器打开」）
- 直接双击本地文件打开的（需要先部署到网上）

## 功能详解

### 存衣服

点右下角「＋」，可以**一次勾选最多 50 张**照片（相册里直接多选）。也支持拖拽进来、直接 Ctrl+V 粘贴。

照片会自动压缩，但**永远保持原始比例**——横图、竖图、方图、极端长图都不会被拉伸或压扁。压缩策略是先按长边缩，体积还是大就逐档降画质，肉眼基本看不出差别。

除了照片，你可以填名字、品牌、标签、备注——**全都可以不填**。想快速存图一秒搞定，想精细管理以后再补。

### AI 识图打标签

传完照片点「🔍 识图填标签」，AI 会看你的衣服然后自动：

- 选品类
- 打颜色、材质、版型、风格标签
- 起名字
- 写英文生图关键词
- 现有标签不够用时，**自己新建标签甚至新建维度**

传了多张时会出现「✨ 一键识图并全部入柜」——每张各自识别、各自打标签、各自入库，不会把 N 件衣服搞成一模一样的记录。

识图清晰度可以在「设置 → 识图」调：节省（512px）、标准（720px）、高细节（1024px，能看清蕾丝纹理和 logo）。

### 分类和标签

默认分类：上装、下装、连衣裙、内衣/睡裙、鞋履、配饰、特殊道具。**可以随便加、改名、删**（删掉的话衣服自动进「未分类」，不会丢）。

标签按维度组织：颜色、材质、版型/细节、风格/场合、角色绑定。每个维度旁边有个 ＋ 可以加新标签，**也可以自己新建一整个维度**（比如「季节」「洗护方式」）。

### 让角色帮你搭配

1. 在试衣间选几件衣服（或点「随机抽一套」，它会按分类各抽一件，凑出真正能穿出门的一整套）
2. 选模式：
   - **只看文本**：他根据标签和备注来搭（快、省 token）
   - **让他看图**：他真的会看照片再点评（更准但更贵，可以选看几张）
3. 点「让他点评并搭配」

他会给一套搭配方案 + 一段点评。你可以：
- **画出返图**：生成你穿这套的效果图
- **发到聊天**：带缩略图的卡片发进跟他的对话，他能针对这套继续聊
- **存进搭配册**：起个名字存起来

### 自己搭配

你也可以自己搭好，然后「请他点评这套」。点评会**先展示在页面上**，你看完满意再决定存不存——不满意可以重新点评。

### 聊天

聊天页是**两级结构**：

```
会话列表（选人）          聊天室（跟某一位对话）
┌──────────────┐        ┌──────────────┐
│ 👤 Antiqua   │  点击   │ ‹  Antiqua   │
│    昨天聊的… │ ─────> │              │
│ 👤 小夜      │        │  ...对话...  │
│    还没聊过  │        │              │
└──────────────┘        │ [输入] ↑  ✦ │
                        └──────────────┘
```

**不同角色的对话完全隔离**，在跟某个人聊的时候不会看到其他人。

**发送和回复是分开的两个键**：

| 键 | 作用 |
|---|---|
| **↑** 发送 | 只把这句加进对话，**他不会回复** |
| **✦** 回复（粉色十字星） | 让他把你刚才说的几句**一起看完**再回 |

这样你就能像发微信那样，一句一句说完再等对方回，而不是说一句他回一句。攒了几句没让他回时，回复键上会显示数字角标。

> 电脑上：回车 = 发送，Ctrl/Cmd + 回车 = 让他回复。

聊天室右上角还有两个小按钮：✎ 编辑这位角色，⌫ 清空跟他的聊天。

### 角色

在「设置 → 角色 → 他们」里管理。每位角色有：

- **头像**：上传任意图片，会自动居中裁成正方形（不会变形）
- **名字**
- **人设**：可以用 `{{user}}` 指代你、`{{char}}` 指代他
- **开场白**：打开聊天时他先说的话
- **气泡颜色**

每位角色的**聊天记录、长期记忆、世界书都是各自独立的**。

「设置 → 角色 → 我」里设置你自己的名字、头像、人设——角色会知道这些。

### 长期记忆

聊久了模型会忘事，所以有记忆系统：每聊够设定的轮数，AI 会自动把这段对话压缩成几条要点存下来，之后一直带在上下文里。

可以手动触发总结、单条删除、全部清空。

### 世界书

聊到关键词时才把对应设定塞给他，省 token。适合放你们的共同回忆、他的背景设定、穿搭偏好规则等。

也可以设成「常驻」——每次都给他看。

### 角色能看到你的衣柜

这是这个 App 的核心。在「设置 → 衣橱联动」里有三档：

| 选项 | 效果 |
|---|---|
| **全部**（默认） | 每件衣服的名字、分类、标签、备注都给他，他能说"穿你那件黑色蕾丝吊带配百褶裙" |
| **只给概况** | 只告诉他件数和各维度分布，省 token |
| **不给** | 他不知道你有什么衣服 |

### 聊天外观

「设置 → 聊天外观」里可以调：

- **背景图**：选一张图铺满聊天区
- **背景压暗**：背景太花时调高，保证字看得清
- **字号**：12 ~ 20px
- **字体**：黑体 / 宋体 / 楷体 / 等宽等
- **文字颜色**：他的气泡和我的气泡分别设置（避免出现黑底黑字）

### 数据管理

| 功能 | 说明 |
|---|---|
| **导出全部数据** | 生成一个 JSON 文件，换手机时用 |
| **导入数据** | 从备份恢复 |
| **清空聊天记录** | 只删所有角色的对话，角色、记忆、衣橱都保留 |
| **删除所有数据** | 恢复成刚装好的样子，需要输入「删除」二次确认 |

## 关于 API

### 兼容性

用的是标准的 **OpenAI 兼容格式**（`/chat/completions`），所以只要是兼容这个格式的服务都能用：官方 OpenAI、各种中转站、自建的 one-api / new-api、SiliconFlow、DeepSeek、OpenRouter 等。

### 流式 / 非流式

不同中转站行为不一样，有的支持真流式（SSE 逐字返回），有的只能返回整块，还有的返回"假流式"。App 默认是**自动模式**：

1. 先试流式
2. 发现对方不支持就自动转非流式，**并记住**，后续不再浪费尝试
3. 兼容"假流式"（content-type 不对但 body 里是 `data:` 行）
4. 兼容 `content` 返回数组分片的接口

也可以在设置里手动强制流式或非流式。

### 识图的实现

识图就是一次普通的 chat 请求，只是 `content` 变成多模态数组：

```json
{
  "model": "gpt-4o",
  "messages": [{
    "role": "user",
    "content": [
      { "type": "text", "text": "识别这件衣服..." },
      { "type": "image_url", "image_url": { "url": "data:image/jpeg;base64,..." } }
    ]
  }],
  "temperature": 0.3
}
```

这是 OpenAI 的标准格式，所有兼容接口都认。图片以 base64 直接传，不经过任何第三方。

### CORS

浏览器直接调接口会有跨域限制。如果你的中转站没开 CORS，会提示「连不上接口」。解决办法：

1. 换一家开了 CORS 的中转站
2. 自己用 Cloudflare Worker 搭个反代（几十行代码）
3. 自建 one-api / new-api 时把 CORS 打开

## 数据存在哪

全部在你自己的设备上，用浏览器的 **IndexedDB**（不可用时自动降级到 localStorage）。

| 存储键 | 内容 |
|---|---|
| `cfg` | 分类、标签池、偏好设置 |
| `it:<id>` | 每件衣服的信息 + 缩略图 |
| `im:<id>` | 每件衣服的高清图 |
| `lk:<id>` | 每套搭配记录 |
| `ai:cfg` | 接口配置（含 Key） |
| `ai:presets` | 你存的接口预设 |
| `roles` / `me` | 角色表 / 你的人设 |
| `msg:<roleId>` | 跟某位角色的聊天记录 |
| `mem:<roleId>` | 跟某位角色的长期记忆 |
| `wb:<roleId>` | 某位角色的世界书 |
| `look` | 聊天外观设置 |

**API Key 只存在本地**，只在调用你自己配的接口时用，不会发给任何第三方。

⚠️ **清浏览器数据会把这些一起清掉**，重要数据记得定期导出备份。

## 常见问题

**Q：识图一直失败怎么办？**

看提示信息：
- 「还没配好接口」→ 去设置里填 Base URL / Key / 模型
- 「这个模型不支持看图」→ 换一个带视觉能力的模型（见上文列表）
- 「连不上接口」→ 检查网络、Base URL 是否写到 `/v1` 为止、是否有 CORS 问题
- 其它错误 → 按 F12 看控制台，会有详细报错

**Q：为什么 iPhone 上装不了？**

必须用 Safari，而且网址必须是 `https://`。点「装到手机桌面」会给你分步说明。

**Q：数据会丢吗？**

只要不清浏览器数据、不卸载就不会丢。但建议定期「导出全部数据」备份一份。

**Q：换手机怎么办？**

旧手机「导出全部数据」→ 把 JSON 文件传到新手机 → 新手机「导入数据」。

**Q：图片会不会太占地方？**

每件衣服存两份：缩略图（约 65KB，列表用）和高清图（约 420KB，放大看用）。100 件衣服大概 50MB 左右。IndexedDB 的容量一般按百兆算，够用。

**Q：能多人用同一个部署吗？**

数据存在各自的浏览器里，所以同一个网址不同的人打开，各自的数据是完全独立的。

**Q：聊天能导出吗？**

「导出全部数据」里包含聊天记录，是 JSON 格式。

## 技术说明

- **零依赖零构建**：整个 App 就是一个 HTML 文件，没有框架、没有 npm、没有打包
- **PWA**：动态生成 manifest（图标用 canvas 画出来），Service Worker 做离线缓存
- **Service Worker 策略**：同源资源缓存优先，导航请求网络优先，**跨域请求完全放行**（保证 AI 接口不被拦截）
- **存储**：IndexedDB → localStorage → 内存，三级降级
- **图片处理**：canvas 等比缩放 + 质量自适应，头像走居中方形裁切
